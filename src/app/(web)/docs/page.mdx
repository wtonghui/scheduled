# 接口文档

> 供外部系统把「定时任务能力」接到本平台。端点前缀 `api/v1`，响应统一信封（错误码见 [§6](#envelope)）。**接口清单里每个接口都有一行真实、可直接粘贴运行的 curl**；字段细节在各小节。

<Note>

**接入前确认**：平台默认用于内网，任务目标地址与回调用例多为内网地址，请确认服务端已设置 `SSRF_ALLOW_PRIVATE=true` / `SSRF_ALLOW_LOCALHOST=true`（元数据主机名等结构性检查始终保留）。系统为多租户：所有资源按调用方 token 的租户隔离，跨租户一律 `404`。

</Note>

<Warn>

**本文示例使用真实可用 token `sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt`（含 `tokens:manage`）**，明文展示于本页——请勿外发本页链接或截图。若需更换，全局替换该 token 即可。

</Warn>

<h2 id="quickstart">1 · 快速开始</h2>

最小闭环：创建任务 → 查执行结果。本文示例统一用下列真实 token 与地址（前端开发可直接照抄）：

```bash
HOST=http://localhost:3000
TOKEN=sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt
```

**① 创建任务**（未签发过 token 的，管理员可用 `tokens:manage` 签发，见第 2 节）

```bash
curl -X POST http://localhost:3000/api/v1/tasks \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ERP 每日对账",
    "cron": "0 1 * * *",
    "taskType": "http",
    "enabled": true,
    "maxAttempts": 3,
    "timeoutMs": 30000,
    "recipients": ["ops@example.com"],
    "notifyOn": ["succeeded", "failed"],
    "webhookUrl": "https://example.com/webhook/scheduler",
    "payload": {
      "url": "http://127.0.0.1:3000/api/v1/healthz",
      "method": "GET",
      "params": { "source": "nightly" },
      "headers": { "Accept": "application/json" },
      "body": null
    }
  }'
```

响应 `201` 返回含 `id` / `version` / `nextRunAt` 的任务资源。完整字段与成功/失败响应见 [创建任务](#ep-tasks-create)。

**② 查执行结果**

```bash
curl "http://localhost:3000/api/v1/executions?page=1&pageSize=20" \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

`data[]` 每项是一次运行，终态 `succeeded / failed / timeout / dead`。字段与成功/失败响应见 [执行结果](#ep-executions)。

<h2 id="auth">2 · 鉴权与 Token</h2>

- **请求头**：写操作、token 管理、全局执行历史与投递日志必须带 `x-api-token: <sche-…>`；任务列表 / 任务详情 / 单任务执行历史支持匿名只读（`writable: false`），外部系统对接请始终携带。
- **token 形态**：`sche-` 前缀 + 48 位；DB 仅存 SHA-256 哈希，`timingSafeEqual` 常数时间比对；**明文仅创建时返回一次**。
- **scope**：token 携带能力声明，缺失即拒绝：

| Scope | 能力 |
|-------|------|
| `tasks:read` | 查看任务、执行历史、邮件/Webhook 投递日志 |
| `tasks:write` | 创建 / 修改 / 删除任务、立即运行 |
| `tokens:manage` | token 列表 / 吊销（管理员专属；签发暂免鉴权） |

- **错误语义**：`401` token 缺失/无效/已吊销；`403` scope 不足（`missing scope: <name>`）；跨租户访问他人资源 → `404`。完整错误码表见 [§6](#envelope)。

管理员签发 / 吊销 token、自查凭证（真实示例）：

```bash
# 签发（免鉴权：无需 x-api-token；返回的 data.token 明文仅此一次，务必保存）
curl -X POST http://localhost:3000/api/v1/tokens \
  -H "Content-Type: application/json" \
  -d '{"name":"erp-integration","scopes":["tasks:read","tasks:write"]}'

# 列表
curl http://localhost:3000/api/v1/tokens \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"

# 吊销
curl -X DELETE http://localhost:3000/api/v1/tokens/<token-id> \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"

# 自查当前凭证（任意有效 token 可调）
curl http://localhost:3000/api/v1/tokens/whoami \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

<Note>

**怎么读这一节**：每个接口一个小节，统一结构——上面是**作用**（一句话讲清它在什么场景用），下面是**参数**（请求体 / 查询 / 路径，含每个字段的用途）→ **调用**（真实可跑的 curl）→ **成功响应**（含逐字段说明）→ **失败**（错误码 / HTTP 状态）。任务、执行、Token、Webhook 投递、邮件日志五类**响应对象**的字段含义在本节「公共响应对象」集中定义一次，各接口的成功响应直接引用，不再重复展开。占位符 `<task-id>` / `<token-id>` 用「创建/签发时返回的 id」替换。

</Note>

### 公共响应对象（字段含义）

> 对象在各接口的 `data` 中复用；时间字段一律为带 `+08:00` 偏移的 ISO 8601（北京时间），`new Date()` 可直接解析。

**Task 对象**（创建 / 列表 / 详情 / 修改返回）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 任务唯一标识；后续按 `:id` 操作 |
| `name` | string | 任务名称 |
| `cron` | string \| null | 5/6/7 段 cron（7 段末位为年；按 `timezone` 解析）；与 `scheduleIntervalSeconds` / `runAt` 三选一 |
| `scheduleIntervalSeconds` | number \| null | 固定间隔（秒，顺延语义）；三选一 |
| `runAt` | string \| null | 一次性时刻（北京时间 ISO）；三选一，跑完自动停用 |
| `timezone` | string | cron/runAt 解析用 IANA 时区（默认 `Asia/Shanghai`） |
| `retryDelayMs` | number \| null | 重试等待基线（毫秒），null=默认退避 |
| `taskType` | `http` \| `noop` | 执行器类型 |
| `payload` | object | 执行负载；`http` 型字段见下，`noop` 型为 `{}` |
| `enabled` | boolean | 是否启用；`false` 时不再调度 |
| `maxAttempts` | number | 同次调度内最多尝试次数（1–10，超时 / 失败会重试） |
| `timeoutMs` | number | 单次执行超时（毫秒） |
| `recipients` | string[] | 终态邮件收件人 |
| `notifyOn` | string[] | 触发通知的终态：`succeeded` / `failed`（邮件与 Webhook 同口径） |
| `webhookUrl` | string \| null | 终态 Webhook 回调地址；未配置为 `null` |
| `nextRunAt` | string \| null | 下次触发时间；停用任务为 `null` |
| `version` | number | 乐观并发版本号；`PATCH` 必须带当前值，冲突返回 `409` |
| `createdAt` / `updatedAt` | string | 创建 / 最后修改时间 |
| `writable` | boolean | 当前查看者是否可写（本租户=true；匿名 / 跨租户只读视图=false）；仅 UI 提示，写操作仍由后端按租户强制 |
| `systemUserId` | string \| null | 系统内用户标识（外部接入系统具体用户）；可选传入（请求头 `X-System-User-Id` 或请求体 `systemUserId`），未传则为 `null` |

`payload`（taskType=http，其中 `params` `/` `headers` `/` `body` 加密存储、读取时解密返回明文）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `url` | string | 目标 URL；创建 / 修改时经 SSRF 校验 |
| `method` | string | `GET` / `POST` / `PUT` / `PATCH` / `DELETE` / `HEAD` |
| `params` | object | URL query 键值，执行时并入 url（原 query 保留 + 同名覆盖） |
| `headers` | object | 请求头（键 → 字符串值） |
| `body` | string \| null | 原始请求体字符串（非 JSON 对象，需自行序列化） |

**Execution 对象**（运行记录，`id` 即 `runId`；执行历史 / 单任务执行历史）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 本次运行唯一标识（= `runId`，Webhook / 邮件 / 日志的幂等键） |
| `taskId` | string | 所属任务 id |
| `scheduledAt` | string | 计划触发时间 |
| `startedAt` | string \| null | 实际开始时间；未开始为 `null` |
| `finishedAt` | string \| null | 结束时间；未结束为 `null` |
| `status` | string | `pending` → `running` → `succeeded` / `failed` / `timeout` / `dead` |
| `attempt` | number | 第几次尝试（1 起，重试递增） |
| `durationMs` | number \| null | 实际耗时（毫秒） |
| `error` | object \| null | 失败详情；成功为 `null` |
| `trigger` | string | 触发方式：`scheduled`（定时）/ `manual`（手动 run-now） |
| `systemUserId` | string \| null | 系统内用户标识（从任务读取并传播到执行记录）；可选传入，未传则为 `null` |
| `createdAt` | string | 记录创建时间 |

`status` 取值：`pending` 已入队待领取；`running` 执行中；`succeeded` 成功（HTTP 2xx）；`failed` 失败（HTTP 非 2xx 或异常）；`timeout` 单次超时（`timeoutMs` 到点，会按 `maxAttempts` 重试）；`dead` 重试耗尽最终失败（死信）。`error` 对象：`class` = `timeout` / `http` / `error`，`error.http` 类还带 `status`（目标返回的 HTTP 码），均可含 `code` / `message` 说明。

**Token 对象**（签发 / 列表；`whoami` 只返回子集 prefix / lastFour / scopes / expiresAt）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | token 记录 id；吊销时用作 `:id` |
| `token` | string | **明文 token，仅签发接口返回一次**，之后不可再取 |
| `prefix` | string | 明文前 6 字符（如 `sche-ige`），肉眼区分用 |
| `lastFour` | string | 明文末 4 字符（如 `tJpP`） |
| `name` | string \| null | 用途备注 |
| `scopes` | string[] | 能力声明：`tasks:read` / `tasks:write` / `tokens:manage` |
| `revokedAt` | string \| null | 吊销时间；`null` = 有效 |
| `lastUsedAt` | string \| null | 最近一次校验成功时间 |
| `expiresAt` | string \| null | 过期时间；`null` = 永不过期 |
| `createdAt` | string | 签发时间 |

**Webhook 投递对象**（单任务投递历史）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 投递记录 id |
| `runId` | string | 关联运行 id（幂等键，同一运行只成功投递一次） |
| `webhookUrl` | string | 回调地址 |
| `status` | string | `pending` / `in_progress` / `sent` / `failed` / `dead` |
| `attempts` | number | 已尝试次数（失败按指数退避自动重试） |
| `signature` | string \| null | 出站签名头 `X-Scheduled-Signature` 完整值 |
| `responseCode` | number \| null | 回调方返回的 HTTP 状态码；未回调为 `null` |
| `sentAt` | string \| null | 成功投递时间 |
| `lastError` | string \| null | 最近一次失败摘要 |
| `systemUserId` | string \| null | 系统内用户标识（通知归属追溯）；可选传入，未传则为 `null` |
| `createdAt` | string | 创建时间 |

**邮件日志对象**（投递日志）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 日志 id |
| `runId` | string | 关联运行 id |
| `toAddress` | string | 收件人邮箱 |
| `subject` | string | 邮件主题（含任务名与结果） |
| `status` | string | `pending` / `in_progress` / `sent` / `failed` / `dead` |

### 公共 · 无需鉴权

<Endpoint id="ep-healthz" method="GET" path="/api/v1/healthz" name="存活探针（不查依赖）" />

**作用**：进程活着即返回 `200`，不检查任何依赖，适合负载均衡器 / k8s `livenessProbe`。

**参数**：无

**调用**

```bash
curl http://localhost:3000/api/v1/healthz
```

**成功（200，实测）**：`{ "status": "ok" }`　**失败**：无

<Endpoint id="ep-readyz" method="GET" path="/api/v1/readyz" name="就绪探针（DB / 邮件 provider）" />

**作用**：检查 DB 与邮件 provider 是否可用，全就绪返回 `200`，任一异常返回 `503`。适合 k8s `readinessProbe` / 网关摘流。

**参数**：无

**调用**

```bash
curl http://localhost:3000/api/v1/readyz
```

**成功（200）**：`data` 为 `db` / `mail` 两项检查结果（`db: "ok", mail: "ok"`）。

**失败（503，实测：本机邮件 provider 未就绪）**

```json
{ "success": false, "error": { "code": "NOT_READY", "message": "not ready", "details": [ { "db": "ok", "mail": "fail" } ] } }
```

<Endpoint id="ep-metrics" method="GET" path="/api/v1/metrics" name="Prometheus 指标（text/plain）" />

**作用**：暴露 Prometheus 格式指标（进程级 + 应用计数器，`content-type: text/plain`），供采集器定时抓取。

### 管理 · token（签发免鉴权；列表 / 吊销需 `tokens:manage`）

<Endpoint id="ep-tokens-create" method="POST" path="/api/v1/tokens" name="签发 token（明文仅此一次）" />

**作用**：创建一个 API token，用于后续所有接口携带 `x-api-token` 头访问。**明文只在本次响应的 `data.token` 返回一次**，务必立即保存——DB 只存 SHA-256 哈希，遗失无法找回，只能重新签发 / 吊销旧的。

**参数**（请求体）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|

### 任务 · tasks（写 `tasks:write` / 读 `tasks:read`）

<Endpoint id="ep-tasks-create" method="POST" path="/api/v1/tasks" name="创建任务" />

**作用**：定义一个定时任务（`cron` / 固定间隔 / 一次性时刻**三选一**），worker 到点领取并执行 `payload` 中的 HTTP 请求；终态按 `notifyOn` 发邮件 + 调 Webhook。返回含 `id`（后续操作用）/ `nextRunAt`（下次触发时间）/ `version`（改造用）的任务对象。

**参数**（请求体，zod 校验）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 任务名称，≤191 字符（展示 / 邮件主题 / Webhook 回调里带） |
| `cron` | string | 三选一 | 5/6/7 段 cron（6 段首位为秒，7 段末位为年）；按 `timezone` 解析 |
| `scheduleIntervalSeconds` | int | 三选一 | 固定间隔，≥1 秒；顺延语义（不对齐整点），与时区无关 |
| `runAt` | string | 三选一 | 一次性时刻（ISO 8601，如 `2027-01-01T09:00:00+08:00`，须未来时间）；到点跑一次后自动停用 |
| `timezone` | string | 否 | cron/runAt 解析用 IANA 时区，默认 `Asia/Shanghai`；仅 cron/runAt 有效（固定间隔为顺延语义，带它直接 400） |
| `retryDelayMs` | int | 否 | 同次调度内重试等待基线 0–3_600_000ms；空=默认退避（1s 起×2/30s 封顶） |
| `overlapPolicy` | string | 否 | 上次未结束时：`skip` 跳过（默认）/ `queue` 排队 / `run` 允许并行；仅重复调度 |
| `endsAt` | string | 否 | 重复调度截止时刻（ISO 8601，须未来）；与 `maxRuns` 可共存（谁先到谁停） |
| `maxRuns` | int | 否 | 重复调度总次数上限（≥1）；调度触发计，run-now/重试/跳过不计 |
| `taskType` | string | 否 | `http` / `noop`，默认 `http` |
| `payload` | object | http 时必填 | 执行负载，字段见下 |
| `enabled` | boolean | 否 | 是否立即开始调度，默认 `true` |
| `maxAttempts` | int | 否 | 同次调度内重试上限 1–10，默认 `3` |
| `timeoutMs` | int | 否 | 单次执行超时 1000–3_600_000ms，默认 `30000` |
| `recipients` | string[] | 是 | 终态邮件收件人，≥1 个合法邮箱 |
| `notifyOn` | string[] | 否 | 触发「邮件 + Webhook」的终态：`succeeded` / `failed`；默认 `["succeeded","failed"]`，只报失败填 `["failed"]` |
| `webhookUrl` | string | 否 | 终态回调地址；出站签名密钥由平台内部生成（不回传） |
| `systemUserId` | string | 否 | 系统内用户标识（可选，≤191 字符）；创建时可通过请求头 `X-System-User-Id` 或请求体传入，头值优先覆盖体值，写入任务表 `system_user_id` |

`payload`（taskType=http）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `url` | string | 是 | 目标 URL；创建 / 修改时经 SSRF 校验（内网部署需开 `SSRF_ALLOW_PRIVATE` / `SSRF_ALLOW_LOCALHOST`） |
| `method` | string | 否 | `GET` / `POST` / `PUT` / `PATCH` / `DELETE` / `HEAD`，默认 `GET` |
| `params` | object | 否 | URL query 键值，执行时并入 url，原 query 保留、同名覆盖 |
| `headers` | object | 否 | 请求头（键 → 字符串值） |
| `body` | string | 否 | 原始请求体字符串（不是 JSON 对象，需自行序列化） |

> **流式响应日志（自动识别，无需配置）**：响应 `content-type` 为 `text/event-stream`（SSE）或含 `ndjson`/`jsonl`/`stream+json` 时，worker 会把流式 body **逐 event/行逐步记录**到日志（`http stream event`），流结束打汇总 `http stream complete`，并在**接口完整跑完后**发送终态邮件。其余类型整包读取并记录完整结果（`http task ok`）。流式任务的 `timeoutMs` 为**空闲超时**：收到任何数据即续命，连续 `timeoutMs` 无数据才判定超时；非流式仍为启动起总时长。日志中的 url 只展示 origin+pathname（并入的 query params 属加密段，不入明文日志）。

**调用**

```bash

  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt" \
```

<h2 id="schedule">4 · 调度参数</h2>

- **三选一强校验**：`cron` / `scheduleIntervalSeconds` / `runAt` 必须恰好一个非空，否则 `400`。
- **cron**：5 段 `分 时 日 月 周`、6 段（首位为秒）或 7 段（Quartz 式 `秒 分 时 日 月 周 年`，如 `0 0 9 1 1 * 2027` 指定 2027 年执行；年份过后无未来运行，任务自动停用），按 `timezone` 解析。
- **一次性**：`runAt` 为 ISO 8601 绝对时刻（须未来时间），到点跑一次后自动停用；与 `cron`/间隔三选一；一次性任务不可配 `overlapPolicy` / `endsAt` / `maxRuns`（只跑一次，无需结束规则）。
- **时区**：`timezone` 为 IANA 名（默认 `Asia/Shanghai`），影响 cron 解析和 runAt 的墙钟上下文；固定间隔为顺延语义无钟表概念，带 `timezone` 直接 `400`。
- **重试等待**：`retryDelayMs` 为同次调度内 attempt 间隔基线（抖动退避×2/30s 封顶保持不变），空=沿用默认。
- **重叠策略**（`overlapPolicy`，仅重复调度）：上次执行未结束又到下次时刻时——`skip`（默认）跳过本次并写 `skipped` 审计行；`queue` 排队等上次跑完（落 `pending` 行，租约释放后被领取）；`run` 允许并行（用户自担双跑风险）。
- **结束规则**（`endsAt` / `maxRuns`，仅重复调度，可共存，谁先到谁停）：`endsAt` 为截止时刻（ISO 8601，须未来），下次运行超出即停用；`maxRuns` 为总次数上限（≥1，调度触发计，run-now/重试/跳过不计），跑满即停用。
- **时间基准**：调度与存储按 UTC 自洽（数据库连接强制 `timezone=Z`）；REST 返回的时间字段一律为带 `+08:00` 偏移的 ISO 8601（北京时间），如 `2026-08-25T10:00:00.000+08:00`，前端 `new Date()` 可直接无损解析。
- **不补跑**：worker 停机错过的运行**不会补执行**，只推进到下一次未来触发（不填历史账）。
- **重试**：`maxAttempts` 为同一次调度内的重试；超时（`timeoutMs`）与失败会重试到终态。

### 5.1 Webhook 回调 <Method method="POST" /> `webhookUrl`（推荐）

任务到终态且 `notifyOn` 包含该状态、并配置了 `webhookUrl` 时，平台向其发起 `POST`（`timeout` / `dead` 按 `failed` 归类），请求体：

```json
{
  "runId": "exXXXX...",
  "taskId": "tkXXXX...",
  "taskName": "每日对账",
  "status": "succeeded",
  "scheduledAt": "2026-08-24T09:00:00.000+08:00",
  "startedAt": "2026-08-24T09:00:00.120+08:00",
  "finishedAt": "2026-08-24T09:00:01.040+08:00",
  "durationMs": 920
}
```

失败时额外携带 `"error": { "message": "<错误摘要>" }`；`status` 取值 `succeeded | failed | dead`（dead = 重试耗尽进死信）。`runId` 全局唯一，消费方应以它做幂等去重。

请求头带签名：`X-Scheduled-Signature: t=<unix 秒>,v1=<hex>`。**验签算法**：对 `t + "." + 原始请求体` 做 HMAC-SHA256，密钥为任务的 `webhookSecret`；`t` 防重放（默认容忍 5 分钟偏差），`v1` 防伪造。

<Warn>

**`webhookSecret` 目前不在任何 API 响应中返回**（创建任务时由平台内部生成，仅用于出站签名）。需要在你的服务端验签的话，请让平台管理员提供该任务的密钥填入下方示例；否则只能校验时间窗口，无法验证签名来源。

</Warn>

Node 验签示例：

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

const secret = "<webhookSecret>"; // 由平台管理员提供（当前 API 不返回该值）
const MAX_AGE_SECONDS = 300;

function verify(body: string, header: string | undefined): boolean {
  const m = /^t=(\d+),v1=([0-9a-f]{64})$/i.exec(header ?? "");
  if (!m) return false;
  const t = Number(m[1]);
  if (Math.abs(Date.now() / 1000 - t) > MAX_AGE_SECONDS) return false; // 防重放
  const expected = createHmac("sha256", secret)
    .update(`${t}.`)
    .update(body)
    .digest("hex");
  return timingSafeEqual(Buffer.from(m[2], "hex"), Buffer.from(expected, "hex"));
}
```

<Danger>

**必须验签**：`t` 防重放、`v1` 防伪造。未验签的回调请求不可信，不应据其触发业务动作。

</Danger>

投递语义：按 `runId` 幂等（同一运行只成功投递一次）；失败走指数退避自动重试；记录查 `GET /api/v1/tasks/:id/webhook-deliveries`。

<h2 id="envelope">6 · 响应信封与错误码</h2>

```json
{ "success": true, "data": { ... }, "meta": { "page": 1, "pageSize": 20, "total": 42 } }
{ "success": false, "error": { "code": "VALIDATION", "message": "...", "details": ["..."] } }
```

| code | HTTP | 含义 |
|------|------|------|
| `VALIDATION` | 400 | 请求体 / 参数校验失败 |
| `UNAUTHORIZED` | 401 | token 缺失、无效或已吊销 |
| `FORBIDDEN` | 403 | 不具备所需 scope（`missing scope: <name>`） |

| `NOT_READY` | 503 | 就绪探针未通过（DB / 邮件） |
| `INTERNAL` | 500 | 服务端内部错误 |

分页：`page` ≥ 1，`pageSize` 1–100（默认 20）；`meta` 恒为 `{ page, pageSize, total }`。

## 系统内用户标识（外接系统具体用户）

外部接入场景中，一个 `api_token` 代表一个外部系统（租户隔离），系统内可能有多个实际用户（不同子账号 / 不同调用方身份）。平台支持区分“系统内哪个用户”创建或触发的任务，便于审计与筛选。

**传递方式（双通道，头优先）**：
- **请求头**：`X-System-User-Id: <标识>`（可选，字符串 ≤191 字符）。用于创建任务（`POST /api/tasks`）、修改任务（`PATCH /api/tasks/:id`）、触发运行（`POST /api/tasks/:id/run-now`）时传递身份；服务端解析后写入任务表的 `system_user_id`（表字段 `system_user_id`）。
- **请求体备选**：任务创建 / 修改请求体中可直接传入 `systemUserId` 字段（可选）；服务端同时解析头与体，头值优先覆盖体值。
- **查询筛选**：任务列表（`GET /api/tasks`）、执行历史（`GET /api/tasks/:id/executions`、`GET /api/executions`）、邮件投递日志（`GET /api/email-log`）、Webhook 投递历史（`GET /api/tasks/:id/webhook-deliveries`）均支持可选查询参数 `?system_user_id=<标识>`，在租户隔离基础上再按系统用户过滤（热路径索引：`Task` 表 `@@index([tenantId, systemUserId, enabled])`）。

**数据模型映射**：
- `Task.system_user_id`（可选，`VarChar(191)`）→ 任务归属的系统内用户。
- `TaskExecution.system_user_id` → 执行记录追溯到同一用户（执行时从任务读取写入）。
- `EmailLog.system_user_id` / `WebhookDelivery.system_user_id` → 通知发件箱记录追溯到同一用户（终态事务写入时从执行记录传递）。

**向后兼容**：字段可为空（`NULL`）；请求头 / 请求体不传时值为 `NULL`，现有查询行为不变。`ApiToken` 表不新增用户字段，系统用户身份仅来自请求传递，不绑定到 token 档案。
