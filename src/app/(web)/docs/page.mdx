# 接口文档

> 供外部系统把「定时任务能力」接到本平台。端点前缀 `api/v1`，响应统一信封（错误码见 [§8](#envelope)）。

<Note>

**接入前确认**：平台默认用于内网，任务目标地址与回调用例多为内网地址，请确认服务端已设置 `SSRF_ALLOW_PRIVATE=true` / `SSRF_ALLOW_LOCALHOST=true`（元数据主机名等结构性检查始终保留）。系统为多租户：所有资源按调用方 token 的租户隔离，跨租户一律 `404`。

</Note>

<Warn>

**本文示例使用真实可用 token `sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt`（含 `tokens:manage`）**，明文展示于本页——请勿外发本页链接或截图。若需更换，全局替换该 token 即可。

</Warn>

<h2 id="quickstart">1 · 快速开始</h2>

最小闭环：创建任务 → 查执行结果。

```bash
HOST=http://localhost:3000
TOKEN=sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt
```

**① 创建任务**（未签发过 token 的，管理员可用 `tokens:manage` 签发，见 [§2](#auth)）

```bash
curl -X POST http://localhost:3000/api/v1/tasks \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ERP 每日对账",
    "cron": "0 1 * * *",
    "taskType": "http",
    "recipients": ["ops@example.com"],
    "payload": {
      "url": "http://127.0.0.1:3000/api/v1/healthz",
      "method": "GET"
    }
  }'
```

响应 `201` 返回含 `id` / `version` / `nextRunAt` 的任务资源，详见 [创建任务](#ep-tasks-create)。

**② 查执行结果**

```bash
curl "http://localhost:3000/api/v1/executions?page=1&pageSize=20" \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

`data[]` 每项是一次运行，终态 `succeeded / failed / timeout / dead`，详见 [执行结果](#ep-executions)。

<h2 id="auth">2 · 鉴权与 Token</h2>

- **请求头**：写操作、token 管理、全局执行历史与投递日志须带 `x-api-token: <sche-…>`；任务列表 / 详情 / 单任务执行历史支持匿名只读。
- **token 形态**：`sche-` 前缀 + 48 位；DB 仅存 SHA-256 哈希，常数时间比对；**明文仅创建时返回一次**。
- **scope**：token 携带能力声明，缺失即拒绝。

| Scope | 能力 |
|-------|------|
| `tasks:read` | 查看任务、执行历史、邮件/Webhook 投递日志 |
| `tasks:write` | 创建 / 修改 / 删除任务、立即运行 |
| `tokens:manage` | token 列表 / 吊销（管理员专属；签发暂免鉴权） |

- **错误语义**：`401` token 缺失/无效/已吊销；`403` scope 不足（`missing scope: <name>`）；跨租户访问 → `404`。完整错误码见 [§8](#envelope)。

签发 / 列表 / 吊销 / 自查 token：

```bash
# 签发（免鉴权；data.token 明文仅此一次，务必保存）
curl -X POST http://localhost:3000/api/v1/tokens \
  -H "Content-Type: application/json" \
  -d '{"name":"erp-integration","scopes":["tasks:read","tasks:write"]}'

# 列表
curl http://localhost:3000/api/v1/tokens \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"

# 吊销
curl -X DELETE http://localhost:3000/api/v1/tokens/<token-id> \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"

# 自查当前凭证（任意有效 token 可调）
curl http://localhost:3000/api/v1/tokens/whoami \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

<h2 id="data-models">4 · 数据模型</h2>

> 以下对象在各接口 `data` 中复用。时间字段一律为带 `+08:00` 偏移的 ISO 8601（北京时间），`new Date()` 可直接解析。

### Task 对象

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 任务唯一标识，后续按 `:id` 操作 |
| `name` | string | 任务名称 |
| `cron` | string \| null | 5/6/7 段 cron；与 `scheduleIntervalSeconds` / `runAt` 三选一 |
| `scheduleIntervalSeconds` | number \| null | 固定间隔（秒，顺延语义）；三选一 |
| `runAt` | string \| null | 一次性时刻（ISO）；三选一，跑完自动停用 |
| `timezone` | string | IANA 时区（默认 `Asia/Shanghai`） |
| `retryDelayMs` | number \| null | 重试等待基线（毫秒），null=默认退避 |
| `startsAt` | string \| null | 开始时刻（ISO）；首跑从此起算 |
| `skipHolidays` | boolean | 到点遇假日是否跳过/顺延 |
| `holidayPolicy` | string | `drop` 作废 / `postpone` 顺延 |
| `overlapPolicy` | string | 重叠策略：`skip`（默认）/ `queue` / `run` |
| `endsAt` | string \| null | 重复调度截止时刻 |
| `maxRuns` | number \| null | 重复调度总次数上限 |
| `consumedRuns` | number | 已消耗配额（调度触发计；与 `maxRuns` 配对看进度，归档不影响） |
| `claimedBy` / `claimedUntil` | string \| null | 当前租约持有 worker / 租约到期时间（null=空闲；过期可被回收重领） |
| `taskType` | `http` \| `noop` | 执行器类型 |
| `payload` | object | 执行负载（`http` 型见下，`noop` 型为 `{}`） |
| `enabled` | boolean | 是否启用；`false` 时不再调度 |
| `disabledReason` | string \| null | 停用原因（写时定夺，持久化；启用中为 null）：`manual` 手动停止 / `run_once_done` 仅执行一次自动停止 / `ends_at` 到截止时间停止 / `max_runs` 到最大执行次数停止 / `no_future_schedule` 无未来计划 / `unknown` 历史未知 |
| `disabledAt` | string \| null | 停用时刻（ISO；启用中为 null） |
| `disabledBy` | string \| null | 停用人：手动=操作 tokenId，自动=worker 实例 id（启用中为 null） |
| `maxAttempts` | number | 同次调度内最多尝试次数（1–10） |
| `timeoutMs` | number | 单次执行超时（毫秒） |
| `recipients` | string[] | 终态邮件收件人 |
| `notifyOn` | string[] | 邮件通知开关（仅控制邮件）：`succeeded` / `failed` / `succeeded_with_results` |
| `webhookUrl` | string \| null | 终态 Webhook 回调地址；有即每个终态必发（不受 `notifyOn` 约束），创建/修改时经 SSRF 校验（与 `payload.url` 同规则） |
| `emailSubjectTemplate` | string \| null | 邮件标题模板（`{placeholder}` 渲染） |
| `emailBodyTemplate` | string \| null | 邮件正文模板 |
| `emailSubjectTemplateFailed` | string \| null | 失败专用标题模板；null=回退成功模板 |
| `emailBodyTemplateFailed` | string \| null | 失败专用正文模板；null=回退成功模板 |
| `emailAttachmentUrlTemplate` | string \| null | 附件 URL 模板 |
| `nextRunAt` | string \| null | 下次触发时间（存储值；详情页“下次运行”优先展示下面的服务端测算） |
| `upcoming` | object \| null | 服务端测算的下一次运行（含节假日/起止/配额；仅详情/创建/更新返回，列表为 null）：`scheduledAt`（string\|null）、`holidayAdjusted`（boolean）、`stoppedReason`（`endsAt`/`maxRuns`/`no-future-schedule`\|null） |
| `version` | number | 乐观并发版本号；`PATCH` 必须带当前值，冲突返回 `409` |
| `createdAt` / `updatedAt` | string | 创建 / 最后修改时间 |
| `writable` | boolean | 当前查看者是否可写（本租户=true） |
| `systemUserId` | string \| null | 系统内用户标识（可选） |

`payload`（taskType=http，`params` / `headers` / `body` 加密存储、读取时解密返回明文）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `url` | string | 目标 URL；创建/修改时经 SSRF 校验 |
| `method` | string | `GET` / `POST` / `PUT` / `PATCH` / `DELETE` / `HEAD` |
| `params` | object | URL query 键值，执行时并入 url |
| `headers` | object | 请求头（键 → 字符串值） |
| `body` | string \| null | 原始请求体字符串（非 JSON 对象） |
| 成败判定 | — | 自动两段式，无需配置：HTTP 非 2xx 按原逻辑失败；2xx 且包体含 `code` 时仅数字 `200` 算成功，其余全失败（`msg` 作失败原因，不重试）；包体无 `code` 则成功 |

### Execution 对象

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 本次运行唯一标识（= `runId`，幂等键） |
| `taskId` | string | 所属任务 id |
| `scheduledAt` | string | 计划触发时间 |
| `startedAt` | string \| null | 实际开始时间 |
| `finishedAt` | string \| null | 结束时间 |
| `status` | string | `pending` → `running` → `succeeded` / `failed` / `timeout` / `dead` |
| `attempt` | number | 第几次尝试（1 起） |
| `durationMs` | number \| null | 实际耗时（毫秒） |
| `error` | object \| null | 失败详情（`class` = `timeout` / `http` / `error`，http 类带 `status`） |
| `trigger` | string | `scheduled`（定时）/ `manual`（手动 run-now） |
| `systemUserId` | string \| null | 系统内用户标识（从任务读取传播） |
| `createdAt` | string | 记录创建时间 |

`status`：`pending` 已入队待领取；`running` 执行中；`succeeded` 成功（HTTP 2xx）；`failed` 失败（HTTP 非 2xx 或异常）；`timeout` 单次超时（会重试）；`dead` 重试耗尽最终失败（死信）。

<h2 id="endpoint-details">5 · 接口详情</h2>

### 公共 · 无需鉴权

<Endpoint id="ep-healthz" method="GET" path="/api/v1/healthz" name="存活探针" />

进程活着即返回 `200`，不检查任何依赖，适合 k8s `livenessProbe`。

```bash
curl http://localhost:3000/api/v1/healthz
```

**成功（200）**：`{ "status": "ok" }`

<Endpoint id="ep-readyz" method="GET" path="/api/v1/readyz" name="就绪探针" />

检查 DB 与邮件 provider，全就绪返回 `200`，任一异常返回 `503`。适合 k8s `readinessProbe`。

```bash
curl http://localhost:3000/api/v1/readyz
```

**成功（200）**：`data` 含 `db` / `mail` 两项（`{ "db": "ok", "mail": "ok" }`）。

**失败（503）**：

```json
{ "success": false, "error": { "code": "NOT_READY", "message": "not ready", "details": [{ "db": "ok", "mail": "fail" }] } }
```

<Endpoint id="ep-metrics" method="GET" path="/api/v1/metrics" name="Prometheus 指标" />

暴露 Prometheus 格式指标（`content-type: text/plain`），供采集器抓取。

```bash
curl http://localhost:3000/api/v1/metrics
```

**成功（200）**：`text/plain` 格式指标文本。

<Endpoint id="ep-docs" method="GET" path="/api/v1/docs" name="OpenAPI 3 文档" />

返回全量 OpenAPI 3 JSON（机器可读规范），可导入 Postman / 生成客户端 SDK。

```bash
curl http://localhost:3000/api/v1/docs
```

**成功（200）**：OpenAPI 3 JSON。

### 管理 · Token

<Endpoint id="ep-tokens-create" method="POST" path="/api/v1/tokens" name="签发 token" />

创建 API token。**明文只在本次响应的 `data.token` 返回一次**，务必立即保存。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 否 | 用途备注 |
| `scopes` | string[] | 否 | `tasks:read` / `tasks:write` / `tokens:manage`；缺省为空 |
| `expiresAt` | string | 否 | 过期时间（ISO 8601）；缺省永不过期 |

```bash
curl -X POST http://localhost:3000/api/v1/tokens \
  -H "Content-Type: application/json" \
  -d '{"name":"erp-integration","scopes":["tasks:read","tasks:write"]}'
```

**成功（201）**：字段见「Token 对象」，其中 `token` 明文仅此一次。

```json
{ "success": true, "data": {
    "id": "cmt6zd2hf0005m0via9u5g4er",
    "token": "sche-…（明文仅此一次）",
    "prefix": "sche-ige", "lastFour": "tJpP",
    "name": "doc-example", "scopes": ["tasks:read"],
    "revokedAt": null, "lastUsedAt": null, "expiresAt": null,
    "createdAt": "2026-08-24T16:34:51.219+08:00"
} }
```

**失败**：`400` 传了不认识的 scope（`unknown scope: xxx`）；`409` 库里尚无默认租户（`BOOTSTRAP_REQUIRED`，先 `npm run seed`）。

<Endpoint id="ep-tokens-list" method="GET" path="/api/v1/tokens" name="token 列表" />

列出当前租户全部 token 记录（不含明文、不含哈希）。

```bash
curl http://localhost:3000/api/v1/tokens \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

**成功（200）**：每项为「Token 对象」（无 `token` 字段）+ `meta`。

**失败**：`401` 无 token / token 无效；`403` 缺 `tokens:manage`。

<Endpoint id="ep-tokens-revoke" method="DELETE" path="/api/v1/tokens/:id" name="吊销 token" />

吊销后该 token 立即失效。**幂等**：对已吊销/不存在的 id 同样返回 `204`。

| 参数 | 位置 | 说明 |
|------|------|------|
| `id` | path | token 记录 id |

```bash
curl -X DELETE http://localhost:3000/api/v1/tokens/cmt6zd2hf0005m0via9u5g4er \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

**成功（204，无响应体）**

**失败**：`401` 无 token；`403` 缺 `tokens:manage`。

<Endpoint id="ep-whoami" method="GET" path="/api/v1/tokens/whoami" name="当前凭证自查" />

返回当前 token 的 scope 与过期时间，用于调试 / 判断权限。

```bash
curl http://localhost:3000/api/v1/tokens/whoami \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

**成功（200）**：「Token 对象」子集。

```json
{ "success": true, "data": {
    "prefix": "sche-sfB", "lastFour": "cMKt",
    "scopes": ["tasks:read", "tasks:write", "tokens:manage"], "expiresAt": null
} }
```

**失败（401）**：`{ "success": false, "error": { "code": "UNAUTHORIZED", "message": "missing x-api-token" } }`

### 任务 · Tasks（写 `tasks:write` / 读 `tasks:read`）

<Endpoint id="ep-tasks-create" method="POST" path="/api/v1/tasks" name="创建任务" />

定义定时任务（`cron` / 固定间隔 / 一次性时刻三选一），返回含 `id` / `nextRunAt` / `version` 的任务对象。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 任务名称，≤191 字符 |
| `cron` | string | 三选一 | 5/6/7 段 cron；按 `timezone` 解析 |
| `scheduleIntervalSeconds` | int | 三选一 | 固定间隔，≥1 秒；顺延语义 |
| `runAt` | string | 三选一 | 一次性时刻（ISO），须未来时间；跑完自动停用 |
| `timezone` | string | 否 | IANA 时区，默认 `Asia/Shanghai`；仅 cron/runAt 有效 |
| `retryDelayMs` | int | 否 | 重试等待基线 0–3_600_000ms；空=默认退避 |
| `startsAt` | string | 否 | 重复调度开始时刻（须未来）；与 `runAt` 互斥 |
| `skipHolidays` | boolean | 否 | 到点遇假日是否跳过/顺延，默认 `false` |
| `holidayPolicy` | string | 否 | `drop`（默认）/ `postpone` |
| `overlapPolicy` | string | 否 | `skip`（默认）/ `queue` / `run`；仅重复调度 |
| `endsAt` | string | 否 | 重复调度截止时刻（须未来） |
| `maxRuns` | int | 否 | 重复调度总次数上限（≥1） |
| `taskType` | string | 否 | `http` / `noop`，默认 `http` |
| `payload` | object | http 时必填 | 执行负载，字段见 [§4 数据模型](#data-models) |
| `enabled` | boolean | 否 | 默认 `true` |
| `maxAttempts` | int | 否 | 重试上限 1–10，默认 `3` |
| `timeoutMs` | int | 否 | 单次超时 1000–3_600_000ms，默认 `30000` |
| `recipients` | string[] | 否 | 终态邮件收件人；缺席/空数组=不发邮件（webhook 照发），默认 `[]` |
| `notifyOn` | string[] | 否 | 仅控制邮件，默认 `["succeeded","failed"]` |
| `webhookUrl` | string | 否 | 终态回调地址；有即每个终态必发（不受 `notifyOn` 约束），与 `payload.url` 同规则做 SSRF 校验 |
| `systemUserId` | string | 否 | 系统内用户标识（≤191 字符）；也可通过请求头 `X-System-User-Id` 传入 |
| `emailSubjectTemplate` | string | 否 | 邮件标题模板（≤255），`{path}` 从响应数据取值渲染 |
| `emailBodyTemplate` | string | 否 | 邮件正文模板（≤10000），同上 |
| `emailSubjectTemplateFailed` | string | 否 | 失败专用标题模板（≤255）；null=回退成功模板 |
| `emailBodyTemplateFailed` | string | 否 | 失败专用正文模板（≤10000）；null=回退成功模板 |
| `emailAttachmentUrlTemplate` | string | 否 | 附件 URL 模板（≤512），渲染后持久化 |

<Note>

**流式响应日志（自动识别）**：响应 `content-type` 为 `text/event-stream`（SSE）或含 `ndjson`/`jsonl`/`stream+json` 时，worker 逐 event/行记录日志；流式任务的 `timeoutMs` 为空闲超时（收到数据即续命）。

**任务执行请求签名**：配了 `TASK_CALLBACK_SIGN_SECRET` 时，http 任务请求自动附带 `X-Scheduled-Signature` / `X-Execution-Id` / `X-Trigger-Type` 三头；未配密钥则原样发出。

</Note>

```bash
curl -X POST http://localhost:3000/api/v1/tasks \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt" \
  -H "Content-Type: application/json" \
  -d '{"name":"ERP 每日对账","cron":"0 1 * * *","taskType":"http","enabled":true,"maxAttempts":3,"timeoutMs":30000,"recipients":["ops@example.com"],"notifyOn":["succeeded","failed"],"webhookUrl":"https://example.com/webhook/scheduler","payload":{"url":"http://127.0.0.1:3000/api/v1/healthz","method":"GET","params":{"source":"nightly"},"headers":{"Accept":"application/json"},"body":null}}'
```

**成功（201）**：字段见「Task 对象」。

```json
{ "success": true, "data": {
    "id": "cmt6yqpo50003m0vispoa9p9h",
    "name": "ERP 每日对账", "cron": "0 1 * * *",
    "scheduleIntervalSeconds": null, "taskType": "http",
    "payload": { "url": "http://127.0.0.1:3000/api/v1/healthz", "method": "GET", "params": { "source": "nightly" }, "headers": { "Accept": "application/json" }, "body": null },
    "enabled": true, "maxAttempts": 3, "timeoutMs": 30000,
    "recipients": ["ops@example.com"], "notifyOn": ["succeeded", "failed"],
    "webhookUrl": "https://example.com/webhook/scheduler",
    "nextRunAt": "2026-08-25T01:00:00.000+08:00", "version": 1,
    "createdAt": "2026-08-24T16:17:28.181+08:00", "updatedAt": "2026-08-24T16:17:28.181+08:00",
```

<Endpoint id="ep-tasks-preview-next-run" method="POST" path="/api/v1/tasks/preview-next-run" name="预演下次运行" />

给**未保存**的调度配置算未来运行（创建/编辑表单边填边看用），纯计算不碰库。`cron` / `scheduleIntervalSeconds` / `runAt` 三选一（与创建同口径）；`from`（ISO 带偏移，缺省 now）、`count`（缺省 1，上限 10）；重复调度的 `consumedRuns` 按 0 算。返回 `runs`（`scheduledAt` + `holidayAdjusted`）与 `stopped`（`endsAt` / `maxRuns` / `no-future-schedule`，还有后续则为 null）。一次性只返回至多 1 条（跑完即止恒为 stopped）；`runAt` 可配节假日（顺延/作废），禁 `endsAt` / `maxRuns` / `startsAt`。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `cron` | string | 三选一 | 5/6/7 段 cron |
| `scheduleIntervalSeconds` | number | 三选一 | 固定间隔（秒，≥1，从 `from` 起算顺延） |
| `runAt` | string | 三选一 | 一次性时刻（ISO 带偏移，必须未来；可配节假日，禁起止/配额） |

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `cron` | string | 与 `scheduleIntervalSeconds` 二选一 | 5/6/7 段 cron |
| `scheduleIntervalSeconds` | number | 二选一 | 固定间隔（秒，≥1，从 `from` 起算顺延） |
| `timezone` | string | 否 | IANA 时区（默认 `Asia/Shanghai`）；interval 下传了会 400（无钟表概念） |
| `startsAt` | string \| null | 否 | ISO 带偏移；只验格式不验未来（预览旧配置直接报 stopped） |
| `endsAt` | string \| null | 否 | ISO 带偏移；命中则 `stopped` 为 `endsAt` |
| `maxRuns` | number \| null | 否 | 1–1000000；`consumedRuns` 按 0 起算，够数即 `stopped` 为 `maxRuns` |
| `skipHolidays` | boolean | 否 | 默认 false；true 要求节假日 API 已配置，否则 400 |
| `holidayPolicy` | string | 否 | `drop`（默认）/ `postpone`；非 drop 必须开 `skipHolidays` |
| `from` | string | 否 | ISO 带偏移，缺省 now；可传未来/过去（如国庆前一天） |
| `count` | number | 否 | 缺省 1，上限 10 |

```bash
curl -X POST http://localhost:3000/api/v1/tasks/preview-next-run \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt" \
  -H "Content-Type: application/json" \
  -d '{"cron":"0 9 * * 1-5","timezone":"Asia/Shanghai","skipHolidays":true,"count":3}'
```

**成功（200）**：

```json
{ "success": true, "data": {
    "runs": [
      { "scheduledAt": "2026-09-15T09:00:00.000+08:00", "holidayAdjusted": false },
      { "scheduledAt": "2026-09-16T09:00:00.000+08:00", "holidayAdjusted": false }
    ],
    "stopped": null
} }
```

`stopped` 非 null 时 `runs` 可能为空（如配额已用尽）；`holidayAdjusted` 为 true 表示该次被节假日调整过（drop 跳过的中间 tick 不展开，只体现在时间差上）。

`stopped` 取值含义（还有后续则为 null；`runs` 非空时也可能同时带 `stopped`，表示“这几 run 完即止”）：

| 取值 | 含义 | 对应调度语义 |
|------|------|--------------|
| `endsAt` | 算出的下一次已超过任务截止时刻，之后不再跑 | claim 侧 `tick > endsAt` 不执行直接停用 |
| `maxRuns` | 按 `consumedRuns` 配额已用尽，再跑一次即超 | claim 侧配额谓词；归档不影响计数，永不复活 |
| `no-future-schedule` | 调度本身算不出未来时间 | 配置无可算调度（前置校验已拦，理论到不了）；或假日 `drop` 把候选全作废且无下一个调度点（366 天全假日的极端） |

**失败**：`400` / `401` / `403`。

<h2 id="schedule">6 · 调度规则</h2>

- **三选一**：`cron` / `scheduleIntervalSeconds` / `runAt` 必须恰好一个非空，否则 `400`。
- **cron**：5 段 `分 时 日 月 周`、6 段（首位秒）或 7 段（Quartz 式 `秒 分 时 日 月 周 年`）；按 `timezone` 解析。
- **一次性**：`runAt` 为 ISO 绝对时刻（须未来），到点跑一次后自动停用；不可配 `overlapPolicy` / `endsAt` / `maxRuns`。
- **时区**：`timezone` 为 IANA 名（默认 `Asia/Shanghai`），仅 cron/runAt 有效；固定间隔带 `timezone` 直接 `400`。
- **重试**：`maxAttempts` 为同次调度内总尝试次数（含初试）；`retryDelayMs` 为重试间隔基线（抖动退避×2，封顶取 30s 与基线较大者）；空=默认退避。
- **开始时间**：`startsAt` 为 ISO 绝对时刻（须未来，仅 cron/interval）；首跑从此起算；与 `runAt` 互斥。
- **节假日**：`skipHolidays=true` 时查日历；`drop`（默认）当次作废取下一非假日点，`postpone` 顺延到下一工作日同墙钟时刻。API 不可达按工作日处理（fail-open）。
- **重叠策略**（`overlapPolicy`，仅重复调度）：`skip`（默认）跳过 / `queue` 排队 / `run` 允许并行。
- **结束规则**（`endsAt` / `maxRuns`，仅重复调度，可共存）：谁先到谁停。
- **结束原因**：任务停用时写 `disabledReason`（`manual` / `run_once_done` / `ends_at` / `max_runs` / `no_future_schedule` / `unknown`）+ `disabledAt` + `disabledBy`；重启用清空。
- **执行进度**：`consumedRuns` 为已消耗配额（调度触发计；与 `maxRuns` 配对看进度，归档不影响）；`claimedBy` / `claimedUntil` 为当前租约持有 worker / 到期时间（null=空闲）。
- **时间基准**：调度按 UTC 自洽；REST 返回 `+08:00` 偏移的 ISO 8601。
- **不补跑**：worker 停机错过的运行不补执行，只推进到下一次未来触发。

查询任务是怎么结束的（详情/列表/创建/更新响应都带这几个只读字段）：

```bash
curl http://localhost:3000/api/v1/tasks/<task-id> \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

```json
{ "success": true, "data": {
    "enabled": false,
    "disabledReason": "max_runs",
    "disabledAt": "2026-09-17T10:35:35.126+08:00",
    "disabledBy": "wk-host-1234",
    "maxRuns": 5,
    "consumedRuns": 5
} }
```

`disabledReason` 取值：`manual` 手动停止 / `run_once_done` 仅执行一次自动停止 / `ends_at` 到截止时间停止 / `max_runs` 到最大执行次数停止 / `no_future_schedule` 无未来计划 / `unknown` 历史未知。启用中三字段为 null。

**配额复活**：`consumedRuns` 是单调账本，编辑任务不会顺手清零。复活走 `PATCH /api/v1/tasks/:id` 显式 `resetConsumedRuns: true`（只能传 `true`，仅停用态可调，记审计日志），常与 `enabled: true` 同包一次提交、原子复活：

```bash
curl -X PATCH http://localhost:3000/api/v1/tasks/<task-id> \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt" \
  -H "Content-Type: application/json" \
  -d '{"resetConsumedRuns":true,"enabled":true,"version":3}'
```

**重启用 fail-fast**：停用任务传 `enabled: true` 时，服务端用生效后值校验——配额仍用尽 / 截止已过 / 调度无未来运行直接 `400`，过了才重算 `nextRunAt` 并启用，不存在“启用成功、下轮又停用”的中间态。

<h2 id="notification">7 · 结果通知</h2>

### 7.1 Webhook 回调 <Method method="POST" /> `webhookUrl`

配置了 `webhookUrl` 的任务，每个终态（成功/失败，含超时与死信归一）必向其发起 `POST`——**只看 url 有无，不看 `notifyOn` / `recipients`**（后两者只控制邮件）。不配则不发。

```json
{ "runId": "exXXXX", "taskId": "tkXXXX", "taskName": "每日对账", "status": "succeeded",
  "scheduledAt": "2026-08-24T09:00:00.000+08:00", "startedAt": "2026-08-24T09:00:00.120+08:00",
  "finishedAt": "2026-08-24T09:00:01.040+08:00", "durationMs": 920,
  "nextRunAt": "2026-08-25T09:00:00.000+08:00", "disabledReason": null }
```

失败时额外携带 `"error": { "message": "<错误摘要>" }`；`status` 取值 `succeeded | failed | dead`。`runId` 全局唯一，消费方应以其做幂等去重。`nextRunAt` 为下次触发时间（北京时间；无后续运行则 `null`，如一次性跑完或任务已停用），`disabledReason` 为停用原因（未停用则 `null`）。

**签名**：与任务执行请求同构的固定密钥签名，请求头带两个：`X-Scheduled-Signature: t=<unix>,v1=<hex>`（对 `t + "." + 原始请求体` 做 HMAC-SHA256，密钥为服务端 `TASK_CALLBACK_SIGN_SECRET`）和 `X-Execution-Id: <runId>`（供对账）。服务端未配密钥时裸发（无签名头，与任务执行请求一致）。`t` 防重放（容忍 5 分钟），`v1` 防伪造；per-task 的 `webhookSecret` 已退场，不再按任务签发密钥。

<Warn>

**密钥交接**：终态 webhook 不再使用 per-task 密钥——接收方用与平台约定的固定共享密钥（`TASK_CALLBACK_SIGN_SECRET`）验签即可；`sign-secrets` 接口的 `webhookSecret` 恒为 `null`，轮换它直接 `400`。

</Warn>

Node 验签示例：

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

const secret = "<TASK_CALLBACK_SIGN_SECRET>";
const MAX_AGE_SECONDS = 300;

function verify(body: string, header: string | undefined): boolean {
  const m = /^t=(\d+),v1=([0-9a-f]{64})$/i.exec(header ?? "");
  if (!m) return false;
  const t = Number(m[1]);
  if (Math.abs(Date.now() / 1000 - t) > MAX_AGE_SECONDS) return false;
  const expected = createHmac("sha256", secret).update(`${t}.`).update(body).digest("hex");
  return timingSafeEqual(Buffer.from(m[2], "hex"), Buffer.from(expected, "hex"));
}
```

<Danger>

**必须验签**：`t` 防重放、`v1` 防伪造。未验签的回调请求不可信，不应据其触发业务动作。

</Danger>

投递语义：按 `runId` 幂等（同一运行只成功投递一次）；失败走指数退避自动重试；记录查 `GET /api/v1/tasks/:id/webhook-deliveries`。`webhookUrl` 与任务 `payload.url` 走同一套 SSRF 校验（含 DNS 复核与重定向逐跳复查）。

### 7.2 邮件通知

配置 `recipients` + `notifyOn` 后终态自动发邮件；投递记录查 `GET /api/v1/email-log`（可按 `runId` / `status` 过滤）。

模板上下文＝内层 `data` 字段平铺＋系统/派生字段：`statusText`（成功/失败）、`failureReason`（外层 `msg` 优先）、`previewTableHtml`（预览表格前 20 行 HTML）、`previewRowsMail`、`previewNote`、`fileSizeText`、`fileDesc`，另有中文别名（`任务名称`、`执行时间`、`执行状态`、`失败原因`、`结果总数量`、`文件格式`、`预览行数`、`预览结果表格`、`文件说明`、`文件链接`、`站内链接`）。缺值替换为空串，未知占位保留原文并打 warn 日志。

失败优先用 `emailSubjectTemplateFailed` / `emailBodyTemplateFailed`（null=回退成功模板）。成败自动判定：HTTP 非 2xx 按原逻辑失败；2xx 且包体含 `code` 时仅数字 `200` 算成功，其余全失败（`msg` 作失败原因，不重试）；包体无 `code` 则成功。无模板时的默认正文仅 Run / Status / Task / Scheduled / Duration。

自定义正文模板会自动美化：模板里的换行保留为换行（不再挤成一段），纯文本形态的 `{文件链接}` / `{站内链接}` 分别渲染成「下载附件」「查看详情」蓝色按钮（URL 只进链接地址；自己手写的链接不动；纯文本版保留裸链接）。推荐模板（每字段一行）：

```
任务名称：{任务名称}
执行时间：{执行时间}
结果总数量：{结果总数量}行
文件格式：{文件格式}
{预览结果表格}
{文件说明}
下载链接：{文件链接}
点击查看本次执行详情：{站内链接}
```

<h2 id="envelope">8 · 响应格式与错误码</h2>

```json
{ "success": true, "data": { ... }, "meta": { "page": 1, "pageSize": 20, "total": 42 } }
{ "success": false, "error": { "code": "VALIDATION", "message": "...", "details": ["..."] } }
```

| code | HTTP | 含义 |
|------|------|------|
| `VALIDATION` | 400 | 请求体 / 参数校验失败 |
| `UNAUTHORIZED` | 401 | token 缺失、无效或已吊销 |
| `FORBIDDEN` | 403 | scope 不足（`missing scope: <name>`） |
| `NOT_FOUND` | 404 | 资源不存在（含跨租户访问） |
| `VERSION_CONFLICT` | 409 | PATCH `version` 与库中不一致 |
| `INTERNAL` | 500 | 服务端内部错误 |
| `NOT_READY` | 503 | 就绪探针未通过（DB / 邮件） |

分页：`page` ≥ 1，`pageSize` 1–100（默认 20）；`meta` 恒为 `{ page, pageSize, total }`。
