# 接口文档

> 供外部系统把「定时任务能力」接到本平台。端点前缀 `api/v1`，响应统一信封（错误码见 [§6](#envelope)）。**接口清单里每个接口都有一行真实、可直接粘贴运行的 curl**；字段细节在各小节。

<Note>

**接入前确认**：平台默认用于内网，任务目标地址与回调用例多为内网地址，请确认服务端已设置 `SSRF_ALLOW_PRIVATE=true` / `SSRF_ALLOW_LOCALHOST=true`（元数据主机名等结构性检查始终保留）。系统为多租户：所有资源按调用方 token 的租户隔离，跨租户一律 `404`。

</Note>

<Warn>

**本文示例使用真实可用 token `sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt`（含 `tokens:manage`）**，明文展示于本页——请勿外发本页链接或截图。若需更换，全局替换该 token 即可。

</Warn>

<h2 id="quickstart">1 · 快速开始</h2>

最小闭环：创建任务 → 查执行结果。本文示例统一用下列真实 token 与地址（前端开发可直接照抄）：

```bash
HOST=http://localhost:3000
TOKEN=sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt
```

**① 创建任务**（未签发过 token 的，管理员可用 `tokens:manage` 签发，见第 2 节）

```bash
curl -X POST http://localhost:3000/api/v1/tasks \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ERP 每日对账",
    "cron": "0 1 * * *",
    "taskType": "http",
    "enabled": true,
    "maxAttempts": 3,
    "timeoutMs": 30000,
    "recipients": ["ops@example.com"],
    "notifyOn": ["succeeded", "failed"],
    "webhookUrl": "https://example.com/webhook/scheduler",
    "payload": {
      "url": "http://127.0.0.1:3000/api/v1/healthz",
      "method": "GET",
      "params": { "source": "nightly" },
      "headers": { "Accept": "application/json" },
      "body": null
    }
  }'
```

响应 `201` 返回含 `id` / `version` / `nextRunAt` 的任务资源。完整字段与成功/失败响应见 [创建任务](#ep-tasks-create)。

**② 查执行结果**

```bash
curl "http://localhost:3000/api/v1/executions?page=1&pageSize=20" \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

`data[]` 每项是一次运行，终态 `succeeded / failed`。字段与成功/失败响应见 [执行结果](#ep-executions)。

<h2 id="auth">2 · 鉴权与 Token</h2>

- **请求头**：除「接口清单」里「公共」分组的 4 个端点外，所有请求带 `x-api-token: <sche-…>`。
- **token 形态**：`sche-` 前缀 + 48 位；DB 仅存 SHA-256 哈希，`timingSafeEqual` 常数时间比对；**明文仅创建时返回一次**。
- **scope**：token 携带能力声明，缺失即拒绝：

| Scope | 能力 |
|-------|------|
| `tasks:read` | 查看任务、执行历史、邮件/Webhook 投递日志 |
| `tasks:write` | 创建 / 修改 / 删除任务、立即运行 |
| `tokens:manage` | 签发 / 吊销 token（管理员专属） |

- **错误语义**：`401` token 缺失/无效/已吊销；`403` scope 不足（`missing scope: <name>`）；跨租户访问他人资源 → `404`。完整错误码表见 [§6](#envelope)。

管理员签发 / 吊销 token、自查凭证（真实示例）：

```bash
# 签发（返回的 data.token 明仅此一次，务必保存）
curl -X POST http://localhost:3000/api/v1/tokens \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt" \
  -H "Content-Type: application/json" \
  -d '{"name":"erp-integration","scopes":["tasks:read","tasks:write"]}'

# 列表
curl http://localhost:3000/api/v1/tokens \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"

# 吊销
curl -X DELETE http://localhost:3000/api/v1/tokens/<token-id> \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"

# 自查当前凭证（任意有效 token 可调）
curl http://localhost:3000/api/v1/tokens/whoami \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt"
```

### 任务 · tasks（写 `tasks:write` / 读 `tasks:read`）

<Endpoint id="ep-tasks-create" method="POST" path="/api/v1/tasks" name="创建任务" />

**参数**（请求体，zod 校验）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | ≤191 字符 |
| `cron` | string | 二选一 | 5 段 cron（默认 Asia/Shanghai 解析） |
| `scheduleIntervalSeconds` | int | 二选一 | 固定间隔 ≥1s；与 `cron` 恰好填一个 |
| `taskType` | string | 否 | `http` / `noop`，默认 `http` |
| `payload` | object | http 时必填 | 见下方 `payload` 表 |
| `enabled` | boolean | 否 | 默认 `true` |
| `maxAttempts` | int | 否 | 1–10，默认 `3`（同次调度内重试） |
| `timeoutMs` | int | 否 | 1000–3_600_000，默认 `30000` |
| `recipients` | string[] | 是 | ≥1 个合法邮箱（终态邮件通知） |
| `notifyOn` | string[] | 否 | 触发通知的终态，默认 `["succeeded","failed"]` |
| `webhookUrl` | string | 否 | 终态回调地址（`secret` 系统生成） |

`payload`（taskType=http）结构

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `url` | string | 是 | 合法 URL；创建时经 SSRF 校验 |
| `method` | string | 否 | `GET`/`POST`/`PUT`/`PATCH`/`DELETE`/`HEAD`，默认 `GET` |
| `params` | object | 否 | URL query 键值，执行时并入 url，同名覆盖 |
| `headers` | object | 否 | 请求头，key → string |
| `body` | string | 否 | 原始请求体字符串（非 JSON 对象） |

**调用**

```bash
curl -X POST http://localhost:3000/api/v1/tasks \
  -H "x-api-token: sche-sfBnRhkMFNiXVUC2Fni6xtPLVZt0T7xhgjb3sfJs2uK3cMKt" \
  -H "Content-Type: application/json" \
  -d '{"name":"ERP 每日对账","cron":"0 1 * * *","taskType":"http","enabled":true,"maxAttempts":3,"timeoutMs":30000,"recipients":["ops@example.com"],"notifyOn":["succeeded","failed"],"webhookUrl":"https://example.com/webhook/scheduler","payload":{"url":"http://127.0.0.1:3000/api/v1/healthz","method":"GET","params":{"source":"nightly"},"headers":{"Accept":"application/json"},"body":null}}'
```

**成功（201，实测）**

```json
{ "success": true, "data": {
    "id": "cmt6yqpo50003m0vispoa9p9h",
    "name": "ERP 每日对账",
    "cron": "0 1 * * *",
    "scheduleIntervalSeconds": null,
    "taskType": "http",
    "payload": { "url": "http://127.0.0.1:3000/api/v1/healthz", "method": "GET", "params": { "source": "nightly" }, "headers": { "Accept": "application/json" }, "body": null },
    "enabled": true,
    "maxAttempts": 3,
    "timeoutMs": 30000,
    "recipients": ["ops@example.com"],
    "notifyOn": ["succeeded", "failed"],
    "webhookUrl": "https://example.com/webhook/scheduler",
    "nextRunAt": "2026-08-24T17:00:00.000Z",
    "version": 1,
    "createdAt": "2026-08-24T08:17:28.181Z",
    "updatedAt": "2026-08-24T08:17:28.181Z",
    "writable": true

```

**失败（400，实测：缺 `payload` / `recipients`）**


<h2 id="schedule">4 · 调度参数</h2>

- **二选一强校验**：`cron` 与 `scheduleIntervalSeconds` 必须恰好一个非空，否则 `400`。
- **cron**：5 段 `分 时 日 月 周`，默认按 **Asia/Shanghai** 解析（支持透传其他 IANA 时区）。
- **时间基准**：调度比较按 UTC 自洽（数据库连接强制 `timezone=Z`）；`nextRunAt` 等一律返回 UTC ISO 8601。
- **不补跑**：worker 停机错过的运行**不会补执行**，只推进到下一次未来触发（不填历史账）。
- **重试**：`maxAttempts` 为同一次调度内的重试；超时（`timeoutMs`）与失败会重试到终态。

### 5.1 Webhook 回调 <Method method="POST" /> `webhookUrl`（推荐）

任务到终态且 `notifyOn` 包含该状态时，平台向 `webhookUrl` 发起 `POST`，请求体：

```json
{
  "runId": "exXXXX...",
  "taskId": "tkXXXX...",
  "status": "succeeded",
  "startedAt": "2026-08-24T01:00:00.120Z",
  "finishedAt": "2026-08-24T01:00:01.040Z",
  "durationMs": 920,
  "error": null,
  "result": null
}
```

请求头带签名：`X-Scheduled-Signature: t=<unix 秒>,v1=<hex>`。**验签算法**：对 `t + "." + 原始请求体` 做 HMAC-SHA256，密钥为任务的 `webhookSecret`；`t` 防重放（默认容忍 5 分钟偏差），`v1` 防伪造。

<Warn>

**`webhookSecret` 目前不在任何 API 响应中返回**（创建任务时由平台内部生成，仅用于出站签名）。需要在你的服务端验签的话，请让平台管理员提供该任务的密钥填入下方示例；否则只能校验时间窗口，无法验证签名来源。

</Warn>

Node 验签示例：

```ts
import { createHmac, timingSafeEqual } from "node:crypto";

const secret = "<webhookSecret>"; // 由平台管理员提供（当前 API 不返回该值）
const MAX_AGE_SECONDS = 300;

function verify(body: string, header: string | undefined): boolean {
  const m = /^t=(\d+),v1=([0-9a-f]{64})$/i.exec(header ?? "");
  if (!m) return false;
  const t = Number(m[1]);
  if (Math.abs(Date.now() / 1000 - t) > MAX_AGE_SECONDS) return false; // 防重放
  const expected = createHmac("sha256", secret)
    .update(`${t}.`)
    .update(body)
    .digest("hex");
  return timingSafeEqual(Buffer.from(m[2], "hex"), Buffer.from(expected, "hex"));
}
```

<Danger>

**必须验签**：`t` 防重放、`v1` 防伪造。未验签的回调请求不可信，不应据其触发业务动作。

</Danger>

投递语义：按 `runId` 幂等（同一运行只成功投递一次）；失败走指数退避自动重试；记录查 `GET /api/v1/tasks/:id/webhook-deliveries`。

### 5.2 邮件通知

配置 `recipients` + `notifyOn` 后终态自动发邮件；投递记录查 `GET /api/v1/email-log`（可按 `runId` / `status` 过滤）。

<h2 id="envelope">6 · 响应信封与错误码</h2>

```json
{ "success": true, "data": { ... }, "meta": { "page": 1, "pageSize": 20, "total": 42 } }
{ "success": false, "error": { "code": "VALIDATION", "message": "...", "details": ["..."] } }
```

| code | HTTP | 含义 |
|------|------|------|
| `VALIDATION` | 400 | 请求体 / 参数校验失败 |
| `UNAUTHORIZED` | 401 | token 缺失、无效或已吊销 |
| `FORBIDDEN` | 403 | 不具备所需 scope（`missing scope: <name>`） |
| `NOT_FOUND` | 404 | 资源不存在（含跨租户访问） |
| `VERSION_CONFLICT` | 409 | PATCH `version` 与库中不一致 |
| `RUN_IN_FLIGHT` | 409 | 存在在途运行，不可删除 |
| `INTERNAL` | 500 | 服务端内部错误 |

分页：`page` ≥ 1，`pageSize` 1–100（默认 20）；`meta` 恒为 `{ page, pageSize, total }`。
